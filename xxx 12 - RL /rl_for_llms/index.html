    RL for Reasoning LLMs¶

    See also: Reinforcement Learning: Principles, Methods, and Frontiers | LLM Post-training

    Opening Briefing¶

    Reinforcement learning has become the primary mechanism for improving reasoning capabilities in large language models. The field moved from PPO-dominated RLHF (2022–2024) to a rapid proliferation of critic-free, group-relative methods optimised specifically for the LLM fine-tuning regime. The key structural insight driving this shift: LLM RL operates from strong pretrained checkpoints, making PPO's variance-reduction machinery (learned critics, GAE) largely redundant — simpler baselines like group means and leave-one-out estimators match or exceed PPO while saving ~50% memory by eliminating the value model entirely.

    A provisional recipe is emerging as of early 2026: critic-free training, token-aware or prompt-aware loss aggregation, softer or more principled trust region handling, and explicit attention to curriculum and compute allocation. DeepSeek-R1 (2025) demonstrated that pure RL can incentivise reasoning capability in LLMs, and subsequent work (GRPO, DAPO, CISPO, Dr. GRPO, MaxRL, DPPO, ScaleRL) has systematically attacked specific failure modes in the training dynamics — loss aggregation bias, gradient masking of important tokens, trust region calibration, and compute allocation across problem difficulty (Alexander Weers, aweers.de, Mar 2026).

    Key: RL for LLMs is no longer bottlenecked by absent algorithms — several workable approaches exist. The harder problems are efficiency (one bit of signal per rollout), robustness (empirical results rarely transfer across model families), generality (progress concentrates in math/code with cheap verifiers), and understanding which improvements survive scale.

    The LLM RL Setup¶

    For LLMs, the standard RL formulation simplifies: a model pi_theta samples responses y ~ pi_theta(·|x) given prompts x ~ D, graded with scalar reward r(x, y). The objective:

    J(theta) = E[r(x, y)] over prompts from dataset D and responses from the policy.

    The gradient has the interpretable form of weighted SFT — sampled responses are reinforced or punished according to rewards. A baseline b(x) reduces variance without changing expected gradients, yielding advantage estimates A_i = r(x,y) - b(x).

    Algorithm Landscape¶

    REINFORCE (Foundation)¶

    The basic policy gradient: log-probability of sampled responses weighted by reward. Main disadvantage is high variance. A baseline reduces variance without bias. All subsequent methods are refinements of how to compute better baselines and control optimisation stability.

    PPO (Proximal Policy Optimization)¶

    Dominated RLHF from 2022–2024. Uses importance sampling ratio clipping (epsilon = 0.2) to limit policy updates, implementing a trust region. Requires a separate value model (critic) trained via GAE for advantage estimation, adding ~50% memory overhead. KL regularisation against a reference policy prevents reward hacking.

    Why it's being replaced: The critic is expensive and, for strong pretrained LLMs, unnecessary — simpler baselines work as well. PPO's clipping mechanism also has subtle failure modes (gradient masking of important tokens).

    GRPO (Group Relative Policy Optimization)¶

    The DeepSeek-R1 breakthrough method. Removes PPO's value model entirely. For each prompt, samples G responses, computes rewards, and normalises within group:

    A_i = (r_i - mu_G) / sigma_G

    This compares responses for the same prompt rather than using learned value functions. The key practical contribution: removing the critic cuts memory use significantly, enabling large-scale reasoning RL (DeepSeek-AI, DeepSeekMath, 2024; DeepSeek-R1, 2025).

    RLOO (REINFORCE Leave-One-Out)¶

    Arrives at similar conclusions from different starting points. For K sampled responses per prompt, the advantage for response i is reward minus the mean of the other K-1 responses:

    A_i = r_i - (1/(K-1)) * sum(r_j for j != i)

    This is an unbiased baseline requiring no learned value model. RLOO drops PPO-style clipping entirely, returning to pure REINFORCE updates. The authors argue clipping is active in less than 5% of cases and may be unnecessary (Ahmadian et al., "Back to Basics", 2024).

    Dr. GRPO¶

    Identifies biases in standard GRPO implementations. Two critical fixes:

    1. Loss aggregation bias: Token losses averaged within sequences then across sequences create incentives favouring short correct responses and long incorrect ones. Fix: divide by a fixed constant (maximum tokens) instead of sequence length.

    2. Standard deviation normalisation hurts: Dividing advantages by sigma_G gives disproportionate updates to nearly-solved prompts where variance is low. Fix: use A_i = r_i - mu_G without standard deviation division (Liu et al., "Understanding R1-Zero-Like Training", 2025).

    DAPO (Decoupled Advantage Policy Optimization)¶

    Four improvements over GRPO:

    1. Token-level aggregation instead of sample-level averaging
    2. Asymmetric clipping — epsilon_low = 0.2, epsilon_high = 0.28, allowing rare low-probability tokens more room to increase
    3. Overlong reward shaping with soft penalty zone before hard cutoff
    4. Dynamic sampling ensuring each prompt has mixed outcomes (some correct, some incorrect) to provide gradient signal

    (Yu et al., "DAPO: An Open-Source LLM RL System at Scale", 2025)

    CISPO (Clipped Importance Sampling Policy Optimization)¶

    Addresses PPO's hard masking of out-of-clip-range tokens. Important reasoning tokens often have low base probability — when their ratios become large, PPO masks them entirely, blocking gradient flow.

    CISPO decouples clipping from gradient flow: clips only the importance-sampling weight and applies stop-gradient, preserving variance reduction while allowing gradients for all tokens. Results: 2x speedup in step-efficiency compared to DAPO (Chen et al., MiniMax-M1, 2025).

    MaxRL (Maximum Likelihood Reinforcement Learning)¶

    Reconceptualises the objective. Standard RL optimises pass@1, but maximum-likelihood training maximises log p_theta(x), which decomposes as an infinite harmonic mixture of pass@k gradients — not just pass@1.

    The on-policy estimator is remarkably simple: average score functions of successful trajectories only. The effective advantage becomes A_i proportional to (r_i - r_hat) / r_hat where r_hat = K/N (success rate). This concentrates learning signal on hard prompts where the success rate is low, and naturally preserves pass@k performance (Tajwar et al., "Maximum Likelihood Reinforcement Learning", 2026).

    DPPO (Divergence PPO)¶

    Questions whether probability ratios are good trust region proxies. Token probabilities can change substantially yet have minimal effect on full-distribution divergence, especially for rare tokens.

    DPPO replaces ratio-based masking with trust regions defined by estimated policy divergence. Binary or top-K divergence approximations work well empirically. Less than 0.5% of updates cause instability; blocking those stabilises training (Qi et al., "Rethinking the Trust Region in LLM RL", 2026).

    ScaleRL¶

    The largest empirical study: 400,000+ GPU-hours of ablations, evaluating methods by fitting sigmoid performance-vs-compute curves. Key findings:

    • Asynchronous RL with continuous rollout generation and immediate updates improves compute efficiency
    • CISPO and GSPO outperform DAPO asymptotically; CISPO selected as default
    • FP32 logits (reducing numerical mismatches between generation and training kernels) substantially improves asymptotic performance
    • Prompt-level loss averaging performs best
    • Zero variance filtering (excluding prompts where all answers are correct/incorrect) accelerates training
    • No positive resampling (excluding prompts with >90% correct) slightly slows training but reaches higher asymptotic performance

    Critical insight: early learning speed and asymptotic performance are separable quantities — interventions that improve one may not improve the other (Khatri et al., "The Art of Scaling RL Compute for LLMs", 2025).

    DVPO (Decoupled Value Policy Optimization)¶

    Removes actor-critic coupling entirely. Instead of co-training a critic model alongside the policy, DVPO provides global value guidance through a decoupled mechanism that does not require a jointly optimised value network. Results: -40% memory usage and -35% training cost compared to PPO-class methods. By eliminating the tight coupling between policy and value estimation, DVPO makes RL for LLMs significantly more cost-optimised for production training loops where memory and compute budgets are binding constraints (arXiv, 2025).

    f-GRPO (f-Divergence GRPO)¶

    Generalises alignment as f-divergence minimization, providing a unified framework that subsumes RLHF, RLVR, and preference optimisation as special cases under different f-divergence choices (KL, reverse KL, Jensen-Shannon, etc.). This reframes GRPO not as a single algorithm but as a family of alignment objectives parameterised by divergence type — choosing the divergence function determines whether the method behaves like reward maximisation, preference matching, or distributional alignment. The practical implication: practitioners can select divergence functions tuned to their task geometry rather than switching between fundamentally different algorithms (arXiv:2602.05946).

    TR-GRPO (Token-Regulated GRPO)¶

    Fixes gradient instability in standard GRPO by identifying that low-probability tokens produce disproportionately large importance sampling ratios, destabilising updates. TR-GRPO addresses this by downweighting low-probability tokens before the ratio calculation, regulating at the token level rather than clipping after the fact. This complements CISPO's approach (which clips importance-sampling weights) and DAPO's approach (which uses asymmetric clipping) — TR-GRPO targets the same instability problem but intervenes earlier in the computation, preventing problematic ratios from forming rather than mitigating them after they arise (arXiv:2511.00066).

    DHPO (Dynamic Hybrid Policy Optimization)¶

    Addresses credit assignment as a multi-scale problem rather than forcing a single granularity. DHPO combines token-level updates (fine-grained credit assignment for individual generation decisions) with sequence-level updates (optimising the true objective over full responses) using entropy-based mixing that dynamically balances the two scales. Separate clipping parameters for each scale prevent the token-level signal from overwhelming the sequence-level objective or vice versa. This reflects the insight that reasoning tasks have structure at multiple levels — individual token choices matter, but so does the coherence of the full reasoning chain (arXiv:2601.05607).

    RLVR (Reinforcement Learning with Verifiable Rewards)¶

    Replaces human preference-based rewards with objective, verifiable checks: unit tests, math proofs, code execution success, formal verification. The reward signal is unambiguous — correct or incorrect — with no subjective interpretation, which produces stronger reasoning and coding gains than preference-based alternatives. The guiding principle: "can this be verified?" matters more than "do humans like this?" for capability training. Recent work extends RLVR to open-ended tasks beyond math and code, broadening its applicability to any domain where automated verification is feasible (arXiv:2511.02463). Critical new finding: verifier noise causes phase transitions in training — when signal quality drops below a threshold, the model doesn't just plateau but actively anti-learns and collapses (arXiv:2601.04411). This means verifier quality matters more than model size for RLVR success. Practical RLVR deployments need redundancy (multiple verifiers), confidence thresholds (discarding low-certainty verdicts), and noise-aware training dynamics to avoid catastrophic training failure from noisy reward signals.

    RLBFF (Reinforcement Learning with Binary Flexible Feedback)¶

    Bridges human preference feedback and verifiable rewards by converting natural language preferences into binary principles. Instead of training a reward model on preference pairs, RLBFF distills preferences into yes/no rules that can be evaluated deterministically — combining the expressiveness of human feedback with the precision of verifiable rewards. Results: beats standard reward models on benchmarks while being cheaper and more interpretable. This positions RLBFF as a practical middle ground for tasks where fully verifiable rewards are unavailable but noisy preference models are insufficient (arXiv:2509.21319).

    d-RLAIF (Direct RLAIF)¶

    Removes the reward model entirely from the RLAIF pipeline, using the LLM directly as the reward function: model generates responses, a judge LLM scores them, and the RL update proceeds without any intermediate reward modeling layer. By collapsing the generate-score-update loop into a tighter cycle, d-RLAIF eliminates reward model training cost and avoids the distribution mismatch between reward model training data and on-policy generations. This represents the logical endpoint of the trend toward simpler RL pipelines — if the judge LLM is capable enough, the reward model becomes unnecessary overhead (PMLR).

    Emerging Consensus¶

    Critics are unnecessary for standard LLM RL — but long-horizon agent tasks are pushing toward "critic-lite." Every method since PPO found that simpler baselines (group means, leave-one-out) match or exceed learned value functions while saving ~50% memory. LLM fine-tuning from strong pretrained checkpoints makes PPO's variance reduction machinery largely redundant. However, pure critic-free methods (GRPO, REINFORCE variants) show instability on long-horizon agent tasks where reward is sparse and delayed. The emerging compromise is minimal critics: lightweight value estimators — not full co-trained critic networks — used solely for variance reduction on the hardest tasks while preserving the memory savings of critic-free approaches for standard reasoning RL. The direction is minimal critics, not zero critics — DVPO's decoupled global value guidance is an early example of this pattern (synthesized from RLHF/GRPO/RLVR research, 2024–2026).

    Standard deviation normalisation tends to hurt. Dividing advantages by sigma adds too much weight on nearly-solved problems, reducing asymptotic performance.

    Loss aggregation is critical — not a minor detail. Sequence-level rewards combined with sample-level averaging distort per-token learning signals. Token-aware or prompt-aware aggregation is now standard.

    Trust regions remain active research. PPO's epsilon = 0.2 works remarkably well, but recent methods improve on it: DAPO relaxes asymmetrically, CISPO clips weights instead of masking gradients, DPPO argues for divergence-based constraints. No consensus yet but continued improvements are likely.

    Policy optimisation is collapsing into three camps. (A) Minimal RL — REINFORCE variants and GRPO-style ranking optimisation, used when reward is noisy or infra budget is constrained. (B) Direct methods — DPO / IPO / KTO variants that avoid an explicit RL loop, used for static preference datasets and alignment tuning. (C) Hybrid loops — alternating supervised updates with RL refinement, emerging as the default for reasoning models and agents. The boundary between these camps is porous: hybrid loops that interleave SFT warm starts with RL refinement are increasingly standard for production systems.

    Reward design matters more than algorithm choice. Across the algorithm landscape, the dominant factor in final performance is reward signal quality — not which policy gradient variant is used. Teams that invest in better verifiers, richer reward decomposition, and calibrated judges consistently outperform those that focus on algorithmic novelty alone.

    Open Problems¶

    Heterogeneous agent collaboration (HACRL/HACPO). Most RL for LLMs assumes a single policy being optimised. Heterogeneous Agent Collaborative Reinforcement Learning (HACRL) introduces a new paradigm where heterogeneous agents share verified rollouts during training to mutually improve, while operating independently at inference time. The corresponding algorithm, HACPO, ensures unbiased advantage estimation and correct optimisation even when rollouts originate from different-capability models. Results: outperforms GSPO by 3.3% using half the rollout cost, suggesting that collaborative training across model families is a viable efficiency lever (arXiv, Mar 2026).

    Credit assignment. Current outcome-based methods assign identical rewards to all tokens in a response. The field is bifurcating into two reward strategies: Process Reward Models (PRM) that reward intermediate reasoning steps (improving reasoning fidelity) and Outcome Reward Models (ORM) that reward final correctness only (scaling better with synthetic data). Beyond PRM/ORM, three newer approaches are emerging for long-horizon agent tasks where credit assignment is especially hard: hierarchical RL (planner model decomposes tasks, executor model acts, credit flows through the hierarchy), retrospective credit assignment (reward assigned after full trajectory analysis rather than per-step), and temporal difference over reasoning steps (adapting TD learning to LLM reasoning chains). No standard approach has emerged, but the problem is increasingly recognised as the primary bottleneck for agent RL.

    Two recent methods attack credit assignment from complementary angles. FA-IRL (Failure-Aware Inverse RL) learns reward functions by focusing specifically on misclassified and ambiguous examples — extracting the true latent reward behind RLHF from where the model is confused, not where it is confident. The training signal comes from failure, not success, making FA-IRL particularly effective at identifying reward features that standard IRL misses because they only manifest at decision boundaries (OpenReview). MA-RLHF (Macro-Action RLHF) operates on phrases and reasoning chunks rather than individual tokens, reducing credit assignment distance by aligning the unit of RL update with the unit of reasoning. Token-level RL is fundamentally misaligned with reasoning tasks where the true decision unit is a reasoning step, not a token — MA-RLHF closes this gap by grouping tokens into macro-actions before computing advantages and applying policy updates (OpenReview).

    Uncertainty-Penalized RLHF. Uses ensemble reward models (LoRA variants sharing a base model) to estimate reward uncertainty, then penalises high-reward but uncertain outputs with reward = value minus uncertainty. This directly targets reward hacking and overfitting — outputs that score high on a single reward model but have high disagreement across the ensemble are downweighted, preventing the policy from exploiting reward model blind spots. By replacing scalar reward with an uncertainty-adjusted signal, this approach provides a principled defense against reward overoptimisation without requiring adversarial training or manual reward capping (ScienceDirect).

    Sample efficiency and trajectory filtering. The information gain in RL is one bit per rollout (correct/incorrect). Current recipes use 8–64 rollouts per prompt for relative baselines — expensive even with automatic verifiers. A promising direction treats agent logs as experience replay buffers — reusing high-quality trajectories and prioritising rare edge cases rather than always sampling fresh rollouts. Techniques include importance sampling for preference data and filtered SFT → RL warm starts (supervised fine-tuning on the best trajectories before RL refinement). This brings LLM RL infra architecturally closer to recommender systems, where offline replay and online learning coexist. More broadly, trajectory filtering is replacing reward shaping as the primary lever for improving RL outcomes. Instead of engineering increasingly complex reward functions, teams aggressively filter trajectories before learning — using top-k selection (keep only the best rollouts), diversity-preserving sampling (ensure the training batch covers distinct solution strategies), and failure clustering (group failure modes to ensure balanced learning signal). The insight: data curation is becoming more impactful than reward engineering — controlling what the model trains on matters more than tuning the scalar signal it trains against (synthesized from RLHF/GRPO/RLVR research + agent RL frameworks, 2024–2026).

    Very hard problems and automated curriculum generation. When models never produce correct rollouts for a prompt, no gradient emerges. Curriculum learning was once a workaround; it is now becoming an automated, first-class component of the RL pipeline. Systems generate tasks just beyond the model's current capability using two complementary techniques: difficulty estimation via success rate (tracking per-prompt pass rates and auto-promoting prompts whose difficulty matches the policy's learning frontier) and adversarial task generators (models trained to produce tasks the policy is likely to fail on). The resulting feedback loop — model fails → generate similar harder tasks → retrain → repeat — replaces hand-curated curriculum schedules with a self-adjusting difficulty ramp. This connects directly to synthetic environment generation: the curriculum generator and the environment generator are converging into a single adaptive system (synthesized from curriculum learning + agent RL frameworks, 2024–2026). Extracting signal from partially correct trajectories and combining search with RL remain important complementary directions.

    Extension beyond math and code — agentic RL as a formal paradigm. Progress concentrates in domains with cheap, unambiguous verification (math, code). Extending to noisy rewards, delayed rewards, subjective evaluation, or multi-turn interaction remains difficult. An early signal that RL can improve agent operational capabilities beyond reasoning: Cursor trained its Composer to self-summarize through RL instead of prompting, cutting context compaction error by 50% and enabling harder long-horizon coding tasks (@cursor_ai, Jun 2026). This suggests RL applied to agent-internal processes (context management, state summarization, tool selection) is a viable and under-explored direction.

    Agentic RL is now a formal subfield in its own right. A comprehensive survey of 500+ works formalises it as a POMDP (Partially Observable Markov Decision Process) problem with four key components: environment interaction, memory, tool-use, and long-horizon planning (OpenReview, "The Landscape of Agentic Reinforcement Learning for LLMs"). This is no longer "LLM + tools" — it is a distinct RL paradigm with its own formulation separate from token-level optimisation. The POMDP framing clarifies why standard token-level policy gradients are insufficient: the agent must reason over partial observations, maintain state across steps, and plan over horizons far longer than a single generation.

    More broadly, RL is shifting from token-level optimisation to trajectory-level optimisation for agentic settings, and the key shift is that environment design now matters more than algorithm choice. Three patterns are emerging: curriculum environments where tasks auto-increase in difficulty as the agent improves, self-play for multi-agent coordination and competition, and tool-augmented RL where the reward signal is tool success (API call results, code execution outcomes, retrieval accuracy). Current project activity concentrates in web agents (browser task completion as reward), coding agents (unit test pass rate as reward), and research agents (citation/retrieval success as reward).

    Tool-use RL is converging on structured action schemas. Instead of exposing raw, unconstrained tool calls as the action space, agent RL systems are moving toward structured action spaces with typed APIs and constrained outputs — where the agent selects from well-defined action types with validated parameters rather than generating free-form tool invocations. This improves both exploration efficiency (the agent searches a smaller, better-structured space) and reward reliability (structured actions are easier to verify and score). The implication is that action space design matters more than RL algorithm choice for tool-using agents — a well-designed action schema with a simple policy gradient outperforms a sophisticated algorithm operating over an unconstrained action space (synthesized from agent RL frameworks including WebArena, SWE-bench, and Voyager-style systems, 2024–2026).

    Experiential RL (ERL) connects directly to the agentic POMDP framing — agents learn from failure trajectories with self-reflection loops, following the pattern: policy → generate → evaluate → store → reuse → improve. This represents RL merging with memory and retrieval for compounding intelligence — the agent does not just update weights but accumulates reusable experience (arXiv, 2025–2026). A more structured variant of self-improving loops is emerging as the practical default: (1) generate trajectories, (2) cluster failures, (3) synthesise new training data targeting failure modes, (4) re-train via SFT or DPO, (5) RL-refine on the hardest remaining cases. This is effectively RL + data engine + eval engine fused into one continuous loop.

    Reward model drift. Static reward models degrade as the policy shifts during training — the reward model was trained on the old policy's distribution and becomes less accurate for the new one. R2M (Real-Time Reward Modeling) addresses this by adapting the reward model to policy distribution shift in real-time, using the policy's internal hidden states rather than static labels to continuously recalibrate reward signals. This represents a shift from static reward functions to online, co-evolving reward models that track the changing policy throughout training (arXiv, 2025).

    Self-synthetic alignment (SAO). Self-Alignment Optimization (SAO) enables fully self-synthetic alignment: the model generates its own prompts, responses, AND preferences — no human labelers or external models needed. Unlike RLAIF (which uses a separate model as judge), SAO uses the model itself for all three roles — prompt generator, response generator, and preference annotator. This drives alignment cost toward near-zero and enables closed-loop autonomous training systems where the model continuously self-improves without external supervision. The implication is a path to alignment that scales without scaling human annotation budgets (arXiv:2510.06652).

    Co-evolution of RL components. Most RL for LLMs treats the reward model and environment as fixed while optimising only the policy. RLAnything challenges this by jointly optimising policy, reward model, and environment in a closed-loop co-evolution system. Instead of treating RL as purely policy optimisation, RLAnything frames it as a system problem where all three components adapt together — the reward model improves alongside the policy, and the environment (prompt distribution, difficulty) evolves to match the policy's current capability frontier (arXiv, 2025).

    LLM-as-judge is becoming part of the RL loop — and judge overfitting is now measurable. Judge models are no longer just evaluation tools — they are serving as reward models, critics, and curriculum generators within the training loop itself. The emerging pattern: model generates → judge LLM scores → policy updates. This creates a new failure mode: reward hacking via judge bias, where the policy learns to exploit systematic biases in the judge (stylistic preferences, formatting heuristics, verbosity bias) rather than genuinely improving. Counter-techniques are maturing beyond ad hoc mitigations into a measurable discipline: cross-judge disagreement scoring (quantifying how much reward varies across different judge models for the same output), judge dropout (randomizing which evaluator scores each rollout, preventing the policy from overfitting to a single judge's idiosyncrasies), style randomization in judge prompts (varying the judge's evaluation framing to reduce exploitable surface area), adversarial judges (trained to resist exploitation), committee/ensemble scoring (multiple judges with diverse biases), and calibrated uncertainty scoring (judges that express confidence, with low-confidence scores down-weighted in reward computation). The emerging meta-metric is robust reward under judge perturbation — measuring whether a policy's reward holds up when the judge ensemble is shuffled or perturbed, rather than trusting a single judge's score (synthesized from judge model research + RLHF/RLVR papers, 2024–2026).

    Safety RL is diverging from capability RL. Separate optimisation pipelines are emerging for capability (math, coding, tool use) and alignment (harmlessness, bias reduction). The capability pipeline uses outcome rewards with synthetic verifiers; the alignment pipeline uses constraint-based RL (KL penalties, rejection sampling) and adversarial red-teaming loops. The divergence reflects a structural tension: capability RL wants to maximise performance on hard tasks, while alignment RL wants to constrain behaviour — and optimising both simultaneously with a single reward signal creates conflicting gradients.

    Synthetic environments are the biggest under-hyped unlock. Instead of relying on human-generated data, the frontier is generating tasks, rewards, and feedback synthetically — math problem generators, code eval harnesses, simulated users. Whoever controls the environment generator controls the learning curve. This connects directly to the RLAnything co-evolution framing: the environment is not a static backdrop but an active component of the training system that evolves alongside the policy. Synthetic environments are especially critical for agent RL, where real-world interaction is expensive and slow — agents will increasingly be trained in simulated worlds before real deployment.

    Inference-time RL is emerging. RL is no longer confined to training — it is creeping into inference. Early directions include test-time search with reward scoring (generating multiple candidates and scoring with a learned reward model before returning the best), dynamic reranking with learned reward models (applying RL-trained value functions to rerank generation candidates at serving time), and speculative decoding with value estimation (using value heads to guide speculative candidate selection). The implication is that training and inference are merging — the boundary between "model that was trained with RL" and "model that uses RL-like search at inference" is dissolving.

    Reward poisoning and RL pipeline security. RankPoison demonstrates a reward poisoning attack that flips preference rankings in RLHF training data, manipulating model behaviour without obvious quality degradation. The attack works by subtly corrupting the preference dataset such that the trained reward model favours attacker-chosen behaviours — and the corruption is difficult to detect because overall dataset quality metrics remain normal. Implication: RL pipelines need dataset auditing and adversarial evaluation as standard security practices, not optional add-ons. This extends to RLVR and RLBFF as well — any reward signal derived from external data is a potential attack surface (ACL Anthology, 2024).

    Empirical reliability. Evidence is empirical, relatively narrow, and expensive to reproduce. Papers typically test one model family, one verifier setup, one dataset, and one budget. ScaleRL shows interventions can change early speed, asymptotic performance, or both — not interchangeably. We know less than appearances suggest.
