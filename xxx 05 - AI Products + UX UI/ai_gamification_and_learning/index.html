    Gamification & Learning Design¶

    Opening Briefing¶

    Most gamified learning platforms face a paradox they refuse to name: the very mechanics that drive engagement — points, streaks, leaderboards — can systematically erode the intrinsic motivation they claim to serve. This is not a hypothetical risk but a well-documented phenomenon in behavioral psychology called the overjustification effect, where extrinsic rewards displace internal curiosity. The design challenge, then, is not how to gamify learning but how to build a reward system that actively monitors and constrains its own incentive structures before they corrupt the learning signal.

    The architecture here addresses this through two interlocking probabilistic models operating on different timescales. FSRS, a three-component memory model tracking per-item difficulty, stability, and recall probability, governs review scheduling by triggering reviews at a 90% predicted recall threshold — a tighter window than traditional SM-2 systems, which rely on fixed intervals and lack per-learner parameterization. Layered on top, a logistic IRT model maintains separate ability (theta) and difficulty (beta) estimates, targeting an 80% success probability per exercise. That 80% figure is not arbitrary: it sits at the empirically validated sweet spot where challenge sustains flow state without triggering the frustration cascades that cause session abandonment. The cold-start problem is handled through an optional 5-minute placement quiz, with full personalization unlocking only after approximately 20 attempts — enough signal for Bayesian updating to converge on a reliable theta estimate.

    What makes this system architecturally distinctive is that it treats its own engagement metrics as potential threat vectors. An explicit "over-grind" guardrail metric tracks the ratio of XP earned from repeated or trivial content versus genuine learning actions. Anti-burnout messages trigger after 20 lessons per day. League participation is opt-out. These are not afterthoughts bolted onto a growth loop; they are first-class system constraints that operationalize the principle that rewards must align with meaningful milestones — skill mastery, project completion — rather than arbitrary accumulation.

    The document that follows specifies this system end to end: from the DAG-structured knowledge graph and JSON exercise schema through the dual-model personalization engine, the carefully gated freemium economy, and a 14-day experiment plan designed to validate whether the retention targets of 45% D1 and 25% D7 hold under real learner behavior. The core operating claim is that game mechanics and learning integrity are not in tension if the system is instrumented to detect when they diverge.

    Executive Summary (Duolingo-Style Platform)¶

    • MVP: Web-based, gamified learning service for technical skills (e.g. Python). 6-10 week build. Targets D1 retention >= 45%, D7 retention >= 25%.
    • Personalized Learning Engine: FSRS (Free Spaced Repetition Scheduler) for review timing + adaptive difficulty via logistic IRT model (inspired by Duolingo's Birdbrain). Target ~80% success probability per exercise. Cold-start via optional 5-minute placement quiz.
    • Core Loop: Learn -> Attempt -> Feedback -> Reward -> Review (repeat). Sessions ~3-5 minutes. Instant feedback, XP rewards, streak tracking.
    • Game Economy: XP (effort), Streaks (habit), Hearts/Energy (pacing), Gems (soft currency), Leagues (social competition, ~30 users, Bronze -> Diamond), Badges (milestones), Quests (weekly goals).
    • Content Model: Knowledge graph (DAG of ~20 skills) with JSON-based lesson schema. ~20 lessons, ~60-80 exercises for MVP. AI-assisted authoring with human review.
    • Animation: Rive for interactive state-machine animations (mascot), Lottie for one-off celebratory effects. Target 60fps, <150KB per asset, respect prefers-reduced-motion.
    • Tech Stack: Next.js PWA + PostgreSQL + Redis (cache/queue) + Background Worker (scheduling, personalization).
    • Pricing: Freemium -- Free tier with ads + 5 hearts limit; Pro ~$10/mo (unlimited hearts, no ads, offline, Practice Hub); Teams (per-seat, admin dashboard).
    • North Star Metric: Weekly Active Learners (WAL) completing >= 1 review.

    Product Requirements¶

    Problem: People start learning programming online but struggle to stay engaged. Traditional courses lack interactivity, feedback, and habit-building.

    Product: Duolingo-like web app breaking skills into small exercises with game mechanics (points, streaks, levels) + spaced repetition + adaptive difficulty. MVP: single track ("Python Foundations").

    Goals & Success Metrics:

    Metric Target
    D1 retention >= 45%
    D7 retention >= 25%
    Avg daily session 5-7 minutes
    Learning efficacy +20% quiz success after spaced reviews
    Content pipeline 100 high-quality exercises (AI-assisted)
    Monetization (v1) >= 5% conversion to paid

    Non-Goals (MVP): Native mobile app, user-generated content, advanced niche topics, full social features, live tutor help.

    Constraints: Accessible (WCAG), works on low-end devices, no gambling mechanics, align with Self-Determination Theory (autonomy, competence, relatedness).

    Success Criteria: "A learner who completes the Python Foundations track can solve 3/5 standard coding challenges (FizzBuzz, file I/O) within 30 minutes." Trial group using spaced reviews scores >15% higher than control. Returning user starts lesson within 3 clicks.

    Learning Model¶

    Knowledge Graph¶

    Directed acyclic graph (DAG) of skills for "Python Foundations":

    Basics -> Variables -> Data Types -> Strings -> Conditionals -> Loops -> Functions -> Lists -> Dictionaries -> Iteration & Algorithms

    Full graph has ~20 nodes. Linear "Path" in UI follows this graph, interleaving review of earlier nodes per spaced repetition.

    Spaced Repetition (FSRS)¶

    • FSRS (Free Spaced Repetition Scheduler): modern three-component memory model -- assigns each item a difficulty, stability (how long until forgotten), and predicts recall probability over time.
    • Reviews triggered when recall probability falls to ~90%.
    • Outperforms older fixed-interval systems (SM-2/Anki) by using ML to personalize intervals per learner.
    • Mastery threshold: item recalled several times in a row + next interval exceeds 60 days -> moves to maintenance review pool.

    Adaptive Difficulty (IRT / Birdbrain-like)¶

    • Each exercise has a difficulty parameter (beta); each user has an ability estimate (theta).
    • Logistic IRT model: P(correct) = sigmoid(theta - beta). Target: ~80% success probability.
    • Theta updated via Bayesian updating or stochastic gradient after each attempt. Beta adjusted if items are consistently too easy/hard across users.
    • After 2-3 consecutive failures, system offers simpler question or hint as a guardrail against frustration.

    Cold-Start Strategy¶

    • Optional placement quiz (5-10 adaptive questions) to estimate initial theta. Users can skip and start from scratch.
    • Full personalization "unlocks" after ~20 attempts when enough data is gathered.

    Game Design¶

    Core Learning Loop¶

    Learn -> Attempt -> Feedback -> Rewards -> Progress & Social -> Review -> (back to) Learn

    Each loop = ~3-5 minutes. Optimized for quick wins and clear endpoints.

    Game Economy¶

    Mechanic Purpose Rules
    XP Effort & competition +10/lesson, +5/review, streak bonus multipliers
    Streak Daily habit Increment daily; streak freeze available (1 gem or auto/week)
    Hearts/Energy Pacing & fail-safe 5 max; -1 per wrong answer; regenerate 1/hour or via practice; Pro = unlimited
    Gems Meta-rewards & currency sink Earn from milestones; spend on streak freeze, hearts, cosmetics
    Leagues Social motivation Weekly XP leaderboard of ~30 users; top 10% promote, bottom 10% demote; opt-out available
    Badges Recognize mastery E.g. "Skill Mastered: Loops", "7-day streak", "100 Lessons"
    Quests Long-term engagement Weekly personal or team challenges for bonus XP

    Anti-grind rules: Cap XP from repeating one lesson; diminishing XP returns for many lessons/day; anti-burnout message after >20 lessons/day.

    Progression Model¶

    • Path: Ordered sequence of circles (lessons) grouped into units (1-2 skills each).
    • Within a unit: 3-5 lessons, then a Review checkpoint (must pass to proceed).
    • Practice Hub: Free review of any skill outside spaced schedule.

    First Session & Day-7 Experience¶

    • Day 0: First lesson is extremely simple (run a print statement). Immediate reward: XP, streak = 1, mascot celebration. Set daily goal.
    • Day 7: User hits a checkpoint, earns a badge ("Python Beginner -- Unit 1 complete!"), sees themselves on a leaderboard. Goal: habit formed (streak ~14) + concrete skill improvement by end of week 2.

    Critical: Drawing on the Octalysis framework -- balance immediate gratification (XP, animations) with longer-term incentives (streak, leagues, badges) without undermining intrinsic motivation. Duolingo's data shows streaks and competition significantly boost engagement, but features must highlight learning gains, not purely extrinsic rewards.

    UX System¶

    User Journeys¶

    1. New User: Sign up -> select track -> optional placement quiz -> Home Path screen -> first lesson (immediate success) -> XP + streak = 1 -> set daily goal. 3 clicks to first lesson.
    2. Returning Daily User: Open app -> review notification ("3 items due") -> complete review (+5 XP) -> next lesson -> earn XP, maintain streak -> check league standing.
    3. Lapsing User (7+ days inactive): Re-engagement email -> "Welcome back" review session -> cracked skills visible on path -> rebuild confidence -> "previous streak: 4" shown -> fresh start encouraged.

    Wireframes (Key Screens)¶

    Screen Layout
    Home/Path Vertical scrolling path of circles (lessons) connected by a line; next lesson highlighted; bottom nav (Home, Practice, Shop, Profile); review indicator
    Lesson Top: progress bar + hearts; center: question/code editor; big tappable answer buttons; inline feedback (green/red); single-focus: one question at a time
    Review Similar to lesson but labeled "Review"; hearts may not apply; skip button available
    Leagues List of ~30 users ranked by XP; league name + days remaining; trophy icons for top 3
    Store Grid of items (Streak Freeze, Heart Refill, avatar cosmetics) with gem prices
    Profile Avatar, username, stats (Level, XP, streak, skills mastered), badges list

    UI/UX Principles¶

    • Clarity: One primary action per screen ("do the next step").
    • Consistency: Same design language throughout (green = correct, red = incorrect, same mascot).
    • Playful tone: Friendly, casual microcopy ("Not quite. Try this: [hint]" / "You nailed it!").
    • Failure-safe: No harsh failure sounds; gentle nudges; after repeated failure, offer easier task for a success moment.
    • Accessibility: Large touch targets, ARIA labels, keyboard navigable, AA contrast, prefers-reduced-motion respected, localization-friendly copy, color-blind safe (icons + text, not just color).

    Microcopy Guidelines¶

    • Tone: Always positive or neutral, never punitive. Encouraging coach persona.
    • Brevity: One sentence or two max. "Great job! You earned 10 XP."
    • Localization-friendly: Avoid idioms or wordplay that don't translate.

    Motion & Audio¶

    Animation System¶

    Tool Use Case Details
    Rive Interactive mascot & state-based visuals States: idle, excited (success), encouraging (mistake), celebrating (level up). State machine transitions driven by app events. Vector-based, ~tens of KB. GPU-accelerated, near-60fps on mobile.
    Lottie One-off celebratory effects Confetti burst (unit complete), spinning coin (XP gain), popping star (level up). Exported from After Effects via Bodymovin. ~50-100KB each. Short playback (<= 1.5s).

    Performance targets: 60fps animations, total animation assets < 1MB for MVP, < 150KB per common file. Fallback to static images on low-power devices.

    Naming convention: motion.success.small, motion.success.big, motion.levelup.big -- central library, Motion Style Guide for consistency.

    Accessibility: Respect prefers-reduced-motion (disable non-essential animations, mascot instant-changes pose). No flashing/strobe effects. Settings: "Animation: Full / Reduced / Off".

    Sound Design¶

    • Correct: gentle "ding" or chime. Incorrect: soft "boop". Level-up: short fanfare.
    • Default low volume, mutable in settings. Always paired with visual feedback (never sole channel).

    Content Ops¶

    Lesson Schema (JSON)¶

    Each lesson targets a skill, contains 3-5 exercises. Exercise types: multiple_choice, fill_in_code, free_response, true_false, short_answer.

    Each exercise includes: prompt, answer, options (for MCQ), distractors, hints (progressive), explanation, tags (skill, difficulty level).

    Authoring Workflow¶

    1. Curriculum design: Outline skill graph; define learning objective per lesson.
    2. AI-assisted generation: LLM produces exercise variants from few-shot prompts; humans review and refine. Duolingo reported AI can produce many exercises that humans then tweak.
    3. Human review & QA: Check clarity, correctness, distractors, bias, difficulty alignment. Every exercise is human-verified -- AI assist is never unchecked.
    4. Beta testing: Small group runs through lessons; telemetry identifies confusing items (e.g., 80% choose wrong answer -> investigate wording).
    5. Continuous improvement: IRT model flags too-easy or too-hard items; content team adjusts or replaces.

    Tagging Taxonomy¶

    • Skill (loops, conditionals), Difficulty (easy, medium, hard -- correlates with IRT beta), Question type (debugging, knowledge, application), Cognitive level.

    Content Scale¶

    • MVP: ~20 lessons, ~60-80 exercises covering Python basics (printing -> functions -> dictionaries).
    • Post-MVP: Add tracks (SQL Basics, Web Dev Basics) using same framework + AI-assisted authoring.
    • A/B test content variants (plain vs. fun-themed wording, 3 vs. 4 MCQ options).

    Architecture & Data¶

    System Architecture¶

    User Device (Browser/PWA) --HTTPS--> Next.js WebApp (Node.js API)
    WebApp --> PostgreSQL (persistent data)
    WebApp --> Redis (cache + job queue)
    WebApp --> Analytics/Telemetry (Segment)
    Redis --> Background Worker(s)
        Worker --> Schedule reviews (FSRS) --> Postgres
        Worker --> Update skill params (theta/beta) --> Postgres
        Worker --> Send notifications --> Push/Email API

    Scalable: Each component (Next.js, DB, worker) independently scalable. Separation of concerns (frontend rendering vs. background calculations).

    Data Model (Core Tables)¶

    Table Key Columns
    users id, username, email, streak, longest_streak, gems, is_premium, current_league_id, goal_minutes
    skills id, name, track, description, order_index, prerequisites
    lessons id, skill_id, title, content (JSONB -- exercises array), unit, position
    items id, skill_id, content (JSONB), base_difficulty, type
    attempts id, user_id, item_id, lesson_id, correct, attempts_count, time_taken, answered_at
    reviews user_id, item_id, next_due, last_seen, stability, difficulty, success_streak (PK: user_id, item_id)
    wallets user_id, gems, hearts
    leagues id, name, tier
    league_memberships user_id, league_id, week_start, xp, rank

    Telemetry Events¶

    user_signup, lesson_start, lesson_complete, item_shown, item_answered (with correct, attempts, answer_time, difficulty_est, user_theta), xp_gained, streak_updated, review_scheduled, league_end, purchase

    Key Metrics Dashboard¶

    Metric Definition Owner
    Weekly Active Learner (WAL) Users completing >= 1 lesson or review/week Product Lead (North Star)
    D1 Retention % of Day0 signups returning Day1 Growth
    D7 Retention % of new users active 7 days after signup Growth
    Avg Daily Minutes Total time in app / DAU Enggmt PM/Design
    Review Completion Rate Reviews completed / reviews scheduled Learning Team
    Average Accuracy % exercises correct on first try Learning Team
    Streak Users % % active users with streak >= 3 Product (Gamification)
    League Churn % users dropping out after end of week Product (Gamification)
    Conversion Rate % active users subscribing to Pro Growth/Monetization
    "Over-grind" metric Proportion of XP from repeating content or trivial actions Guardrail

    Infrastructure: Next.js on Vercel/Node server. Postgres on managed cloud DB. Redis likewise. Workers via PM2 or serverless scheduled functions. Analytics via Amplitude/Mixpanel. GDPR-compliant (deletion process, no PII in events).

    Go-to-Market & Pricing¶

    Two Product Plans¶

    Plan A: "Path & Reviews MVP" Plan B: "Projects & Quests"
    Target Individual learners (students, professionals) Project-oriented learners, bootcamp students
    Value Prop "Learn coding in 5 minutes a day" "Learn by doing -- build mini-apps from day one"
    Core Features Guided path, daily reviews, gamification Weekly "Quest" projects broken into daily tasks
    Timeline MVP (6-10 weeks) Introduced after MVP once core loop validated (~Month 4)

    Plans can be combined in v1: first month = fundamentals path (Plan A), second month = capstone project (Plan B).

    Pricing Tiers¶

    Tier Price Includes
    Starter (Free) $0 All lessons, spaced reviews, basic league, community. Limits: 5 hearts, ads, no offline
    Pro ~$10/mo Unlimited hearts, no ads, offline access, Practice Hub, advanced analytics, cosmetics
    Teams/Enterprise Per-seat (~$100/yr) Teacher/admin dashboard, group progress tracking, private leaderboards, SSO, custom content

    Feature gating: Pro features behind feature flags for A/B testing. Don't hardwall curriculum -- monetize on convenience (unlimited hearts, no ads, offline). 7-day free trial of Pro.

    Marketing: Viral loops (share streak/progress), referral bonuses (gems for inviting friends), SEO content ("Python Tip of the Day"), Product Hunt launch, "14-day coding streak challenge" on social media.

    A/B Testing Roadmap (First 8 Weeks Post-Launch)¶

    Experiment Hypothesis Metric Sample
    Home CTA Clarity Big "Continue" button vs. tapping lesson circle on path Session start rate ~200/variant
    Streak Freeze: Auto vs. Manual Auto-applying one free freeze on missed day improves Day-8 retention Day-8 retention among users who missed a day ~100/group who miss a day
    Adaptive Difficulty On/Off Birdbrain-like personalization improves success rate + engagement % correct on first try, 14-day retention ~few hundred, 3-4 weeks
    Animation Delight (Rive vs. Static) Animated feedback (mascot + Lottie confetti) increases next-day return Next-day retention, session length 100-200/group

    Risks & Mitigations¶

    Risk Mitigation
    Extrinsic motivation crowding out intrinsic (overjustification effect) Tie rewards to meaningful milestones (mastering a skill, completing a project). Offer user choice (path branching). Emphasize personal progress ("You solved a tough problem!"). Monitor via surveys. Guardrail metric: ratio of learning actions to XP-grinding actions.
    Leaderboard toxicity & competition stress Opt-out (private profile removes from leaderboard). Tier matching by activity level. Positive framing (show personal bests, not "others ahead of you"). Weekly resets prevent long-term discouragement. Leagues capped at 30. Explore cooperative goals in future.
    Cheating & abuse Server-side answer validation. Rate limits (can't complete 100 lessons/hour). Limited payoff for cheating (no cash prizes, just leaderboard rank). Community guidelines + moderation for social features. Parameterized queries for security.
    Content quality & mislearning Rigorous human review cycle. Beta test with small group. In-app "report issue" button. IRT model flags too-easy/too-hard items. Smooth difficulty ramp. Real-world tasks early for intrinsic payoff.
    Accessibility gaps WCAG compliance (semantic HTML, ARIA, keyboard navigation, AA contrast). prefers-reduced-motion honored. Captioning for any audio. Accessibility audit pre-launch.
    Scalability & downtime Managed cloud services. Monitoring & alerts. Daily DB backups. Graceful in-app error handling + offline fallback. Manual fallback for personalization service failure.
    Legal/privacy GDPR/COPPA compliance. Privacy policy. Deletion process. No PII in analytics events. Target 13+ initially. No verbatim copyrighted code in AI-generated content.
    Motivation drop if progress lost Streak freeze + possible streak pause for vacations. Show "previous streak" to remind of past success. Failed checkpoint = "another practice round" not a hard fail. Celebrate effort, not just consistency.
    Team/guild dynamics (if introduced) Team activities optional. Cooperation > internal competition. Moderator tools. Anonymity/aliases on public leaderboards.

    First 14 Days: Experiment & Execution Plan¶

    Day Key Actions
    0 (Launch) Deploy MVP (Plan A). Soft launch to 50-100 users. Start Experiment 1 (Home CTA) 50/50 split. War room monitoring.
    1 Check D1 retention. Fix content errors. Open to more users.
    2 Email campaign ("complete a lesson to keep your streak!"). Plan Experiment 2 (Streak Freeze) groups.
    3 Interim analysis of Experiment 1 (~3 days data). Data check: drop-off patterns, hint usage. Team reviews KPIs vs. targets.
    4 Implement Experiment 1 decision. Start Experiment 2 (Streak Freeze auto). Start Experiment 3 (Adaptive On/Off) for new sign-ups. Draft Day-7 survey.
    5 Check Day-3 retention for Day0 cohort. Address drop-off patterns. Leagues may have enough users.
    6 Weekend -- send Day-7 survey to early users. Implement minor UI improvements.
    7 Weekly league reset. Measure D7 retention. Conclude Experiment 2 (Streak Freeze). Internal week-1 report. 7-day streak promo badge/email.
    8 Start Experiment 4 (Animations on/off). Check Experiment 3 (Adaptive) for earliest cohort. Check monetization flows.
    9 Content expansion/tweaks. Review survey results. Soft-launch Plan B project beta if applicable.
    10 Marketing push #2 (success story/testimonial). Check league churn anomalies. Evaluate Experiment 4 early signals.
    11 Plan Week 3 features (referral program?). Content team creates weekend challenge.
    12 Conclude Experiment 3 (Adaptive). Look at conversion data. Start "Week 2 Progress" blog post.
    13 Push weekend challenge notification. Evaluate Experiment 4 initial results. Re-engagement email to inactive users.
    14 Collect D14 retention metrics. Summarize all experiments. Team retrospective. Plan next sprint. Soft-launch Pro feature. Thank-you message to user community.

    Critical: The first 14 days follow a rapid "build-measure-learn" cadence -- 1-2 experiments at a time, each with a defined hypothesis, metric, and sample size. By Day 14: key retention numbers, initial data on gamification features, and a refined plan for scaling.
