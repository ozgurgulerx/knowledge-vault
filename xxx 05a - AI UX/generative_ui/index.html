    Generative UI¶

    See also: AI UX — broader AI UX frameworks, design patterns, and agent UX architecture

    Opening Briefing¶

    Generative UI is the paradigm where AI models produce entire interactive user interfaces — not just text responses — dynamically tailored to each prompt. The interface itself becomes a runtime artifact compiled from intent, not a screen designed by a human. Google Research's implementation ("Generative UI: LLMs are Effective UI Generators") is the first major deployed system, shipping in the Gemini app and Google Search AI Mode. The core architectural insight is that the model generates complete HTML/CSS/JS output guided by system instructions, tool access, and post-processing — producing web pages, games, tools, dashboards, and simulations on the fly. As of 2026, generative UI has evolved from a research demo into a first-class runtime layer, with interfaces that are context-personalized at generation time (e.g., same topic → different UI for a child vs. an expert) and human evaluators consistently preferring generated interfaces over text responses when latency is ignored (Google Research, 2025).

    Google Research Implementation¶

    Architecture¶

    The implementation uses Gemini 3 Pro with three additions on top of the base model (Yaniv Leviathan, Dani Valevski, Vishnu Natchu, Yossi Matias, Google Research, Nov 2025):

    1. Tool access — a server provides key tools (image generation, web search). Results can be sent to the model to increase quality or directly to the user's browser for efficiency.
    2. Carefully crafted system instructions — detailed instructions covering goal, planning, examples, technical specifications, formatting, tool manuals, and tips for avoiding common errors.
    3. Post-processing — model outputs pass through post-processors to address common issues before rendering.

    The pipeline:

    User prompt → LLM (with system instructions + tools) → HTML/CSS/JS → User's browser

    Styling Control¶

    The implementation supports two modes:

    • Product-consistent styling — all results, including generated assets, created in a consistent visual style for all users (useful for branded products)
    • Automatic / user-influenced styling — the model selects style automatically, or the user influences it via their prompt (as in dynamic view)

    Evaluation: PAGEN Dataset¶

    Google created PAGEN, a dataset of human expert-made websites designed to facilitate consistent evaluation and comparison of generative UI implementations. PAGEN will be released to the research community.

    Preference evaluation results (ignoring generation speed):

    1. Human expert-designed sites — highest preference rates
    2. Generative UI implementation — close second, with a substantial gap above all other output methods
    3. Standard formats (top Google Search result, raw LLM text, markdown) — significantly lower preference

    Key: Generative UI quality depends strongly on the underlying model's capability — newer, more capable models perform substantially better. This means generative UI quality will improve automatically as foundation models improve.

    Product Deployments¶

    Gemini App¶

    Two experiments rolling out:

    • Dynamic view — Gemini designs and codes a fully customized interactive response for each prompt using agentic coding capabilities. The model understands that explaining the microbiome to a 5-year-old requires different content and features than explaining it to an adult, and that creating social media posts requires a completely different interface from generating a trip plan.
    • Visual layout — a complementary experiment (users may initially see only one of the two)

    Use cases demonstrated: learning about probability, event planning, fashion advice, Van Gogh galleries with life context, teaching mathematics, exploring fractals.

    Google Search AI Mode¶

    Generative UI integrated into AI Mode in Google Search, powered by Gemini 3's multimodal understanding and agentic coding. The model interprets prompt intent and builds bespoke interactive tools and simulations optimized for comprehension and task completion. Available for Google AI Pro and Ultra subscribers in the U.S. via the "Thinking" model drop-down in AI Mode.

    Example use case: interactive visualization of RNA polymerase transcription stages showing differences between prokaryotic and eukaryotic cells.

    Google Stitch ("Vibe Design")¶

    Google launched Stitch (stitch.withgoogle.com) as a productized "vibe design" tool — an intent-first design paradigm where input is goals, mood, and desired outcomes, and output is full interactive UI with flows. Stitch represents a step beyond generative UI as response: the system critiques its own designs in-loop, generates next screens proactively, and treats UX as an exploration space rather than a fixed artifact. The infinite canvas + auto-generated user journeys + voice interaction combine into a design workflow where the AI is a co-creative agent, not an editor. This signals design tools becoming agent-like systems that participate in the design process rather than merely executing instructions (Google, TechRadar, Mar 2026).

    What Generative UI Produces¶

    The model generates complete interactive artifacts, not templated responses:

    • Web pages — fully custom layouts with styled content
    • Games — interactive playable experiences
    • Tools — calculators, planners, converters, simulations
    • Dashboards — data visualizations with charts and controls
    • Educational interfaces — adaptive content based on audience expertise level
    • Applications — forms, galleries, interactive explorations

    Each output is fully customized to the specific prompt — from a single word to elaborate multi-paragraph instructions.

    Self-Adapting and Dynamic Interfaces¶

    Generative UI sits at the far end of a broader shift toward self-adapting interfaces that reorder layout based on behavior, generate UI on demand, and optimize in real-time (Design Studio UX, 2025). Where traditional adaptive UX tweaks component placement or theming, generative UI extends this to full layout synthesis — the entire interface is a generated artifact (Vocal, 2026).

    The latest prototypes push further: generated UI is evolving from rendered views into stateful execution surfaces. UI elements are bound to live tool calls, components persist and evolve across turns, and the generated interface maintains state that outlives any single interaction. The shift is from "render UI" to "instantiate an interactive system" — the UI becomes a thin wrapper over the agent runtime, not a presentation layer separate from it. This collapses the traditional boundary between frontend and agent execution: the interface is the running system, not a window into it (arXiv, generative UI systems, 2025–2026).

    This changes the designer's role fundamentally: the job becomes policy and constraint design, not layout authorship. Designers define the rules, tokens, and boundaries; the model handles composition.

    Dynamic Modality¶

    A 2026 framework formalizes how interface modality should shift based on task complexity, autonomy level, and reasoning depth (arXiv, "Interface Framework for Human-AI Collaboration," 2026). The resulting spectrum:

    prompt bar → chat → workspace → autonomous agent UI

    Interfaces will increasingly shift modes mid-task — a query that starts as a chat response may escalate to a generated workspace when the model detects the user needs richer interaction. This is a natural extension of generative UI: the system doesn't just generate a single interface, it selects and transitions between interface modalities dynamically.

    Oversight and Safety as Interface Primitives¶

    One of the most consequential developments in generative UI is the recognition that the interface is now part of the safety system, not just presentation. "Oversight-by-design" embeds risk signals directly in the UI, automatic escalation to human review, and audit/traceability hooks as first-class interface components (arXiv, "Human Oversight-by-Design for Generative IUIs," 2026).

    This connects directly to the contracts framework: generative UI without governance guardrails is fragile. The oversight layer ensures that generated interfaces don't just look right — they behave safely by surfacing uncertainty, flagging risk, and routing decisions to human review when confidence is low.

    Failure-Aware UI Components¶

    As generative UI matures, the interface must handle failure modes that go beyond hallucination into structural territory:

    • Reward hacking — models optimize proxy signals instead of real intent (e.g., sycophancy, generating verbose but unhelpful UIs) (Wikipedia, "Reward hacking")
    • Interaction-level failures — trust miscalibration (users over- or under-relying on generated UI), poor mental models of what the interface can do, weak recovery UX when things break (Medium, "UX Research for AI Products")
    • System-level failures — oversight gaps where generated UI bypasses review, escalation failures where the interface doesn't route to humans when it should, workflow brittleness where generated interfaces break under edge cases

    Key: Failure is shifting from output quality → interaction dynamics → system-level brittleness. Generative UI design must account for all three layers.

    The Terminal Paradigm and Agent UX¶

    Research on agent-facing interfaces reveals that terminal-style UX is quietly winning as the dominant pattern for human-agent collaboration. Terminal interfaces dominate because they provide transparent action traces, low abstraction overhead, and easy intervention points (arXiv, "Terminal Is All You Need," 2026).

    The design implication for generative UI: future generated interfaces will likely simulate terminal properties — visible logs, step-by-step execution traces, diffs of state changes — even when wrapped in graphical chrome. The tension is between the polish of generated UIs and the transparency of terminal-style interaction. The best generative UI systems will offer both: a clean generated interface with an "inspect mode" or "debug view" that exposes the underlying action trace.

    Conversational UX → Multi-Modal Orchestration¶

    Chat is becoming an entry point, not the primary interface. Systems increasingly combine chat + generated UI + tools + agents into orchestrated workflows. The pattern:

    conversation → orchestration → generated workspace

    This reframes generative UI as one modality within a larger orchestration layer. The model doesn't just generate a UI — it generates the right combination of modalities for the task. A financial analysis prompt might produce a chat explanation, a generated dashboard, a connected spreadsheet tool, and an agent monitoring data feeds — all coordinated.

    "Truman-Style" Interaction (Emerging Pattern)¶

    An emerging and somewhat speculative pattern: AI invisibly orchestrates tools, UI, and workflows so that the user experiences a seamless environment with minimal explicit control. The AI handles tool selection, interface generation, and workflow routing behind the scenes.

    The tension is clear: usability goes up, but mental model clarity goes down. Users may not understand what the system is doing or why. The emerging counter-pattern is "inspect mode" / "debug view" — giving users the ability to peel back the orchestration layer and see the machinery. This maps directly to the terminal paradigm insight above.

    A concrete manifestation of Truman-style interaction is latent task queues — the system accumulates inferred tasks and pending actions based on context signals (conversation history, environment events, user patterns) and executes them when a confidence threshold is met or the user implicitly approves. The risk is twofold: unexpected actions (the system does something the user never explicitly requested) and backlog explosion (the queue grows faster than the system can process, creating invisible technical debt). The emerging mitigation is a "pending intentions" inbox UI — a visible queue where users can review, approve, defer, or dismiss system-inferred tasks before execution. This preserves the seamless feel of Truman-style orchestration while giving users a single surface for oversight of what the system plans to do autonomously (arXiv, agent systems, 2025–2026).

    AI UX as System Design¶

    A 2026 framework reframes AI UX as spanning three domains simultaneously (arXiv, "Beyond the Interface: Society-in-the-Loop AI Systems," 2026):

    1. Model performance — what the AI can actually do
    2. Human workflows — how people integrate AI outputs into decisions
    3. Governance + escalation — who reviews, overrides, and audits

    Core metrics shift accordingly: accuracy measured by decision impact (not just output correctness), operational latency, adaptation cost (how hard it is to adjust the system), and trust calibration (whether users trust the system appropriately).

    UX moves from screens to end-to-end decision systems. For generative UI specifically, this means the generated interface is evaluated not just on visual quality or interactivity, but on whether it leads to better decisions in the workflow it serves.

    HAX Toolkit as Failure Engineering¶

    Microsoft's HAX (Human-AI eXperience) toolkit is evolving from UX guidance into a failure engineering system (Microsoft Research). The core stack — guidelines (behavior), design patterns (solutions), workbook (planning), playbook (failure simulation) — is increasingly used as a pre-mortem system for AI failures: systematically simulating how generated interfaces might fail before deployment, rather than just guiding their design.

    Design Implications¶

    The Generation Spectrum¶

    Generative UI exists on a spectrum of model control over the interface:

    Level How It Works Trade-off
    Static (slot filling) Model fills copy, labels, hints within fixed layouts Safest; limited flexibility
    Declarative (component assembly) Model selects from registered component library via typed schema Best balance of flexibility and reliability
    Fully generated Model emits raw HTML/CSS/JS (Google Research approach) Maximum flexibility; hardest to govern

    Google's implementation operates at the fully generated level — the model produces raw web code — but relies on system instructions and post-processing to maintain quality.

    Contracts Before Intelligence¶

    Five contracts should be in place before any model touches interface generation:

    1. UI schema (DSL) — typed JSON/YAML describing pages, layouts, components, bindings
    2. Design system primitives — tokens, layout primitives, stable component library with accessibility guarantees
    3. Capability map — what the app can do; the model composes only from declared capabilities
    4. Policy and safety — allowlists, prop constraints, data scopes, redaction rules
    5. Observability — structured logs feeding evaluation loops

    Google's approach uses system instructions and post-processing rather than a formal DSL, trading some governance rigor for maximum generative flexibility.

    From Components to Protocols¶

    The next evolution beyond contracts is defining UI generation protocols — standardized specifications for how models produce interfaces, replacing ad-hoc rendering with structured outputs. Instead of models emitting free-form HTML, they output structured UI schemas, event bindings, and tool contracts that a deterministic renderer interprets. This enables three properties that free-form generation cannot guarantee: deterministic rendering (same schema always produces the same interface), cross-platform portability (schemas render natively on web, mobile, or desktop), and safety constraints at the schema level (invalid actions are structurally impossible, not just filtered). The protocol approach moves generative UI from "model generates code" to "model generates intent in a constrained language" — a fundamental shift toward verifiable interface generation (arXiv, generative UI systems, 2025–2026).

    Macro Trajectory¶

    The field is converging toward a three-layer architecture:

    1. Intent layer — natural language / goals (what the user wants)
    2. Orchestration layer — agents + tools + plans (how to achieve it)
    3. Interface layer — generated + adaptive UI (how to present it)

    The hardest open problem: making the orchestration layer visible without overloading the user. Generative UI solves the interface layer; the orchestration layer — where agents coordinate, select tools, and manage state — remains the frontier of AI UX design.

    Current Limitations and Open Research¶

    • Generation speed — current implementations can take a minute or more to generate results, a significant UX constraint for interactive use
    • Occasional inaccuracies — model outputs may contain errors in the generated interface logic or content
    • Model dependency — quality is tightly coupled to the underlying model's coding and reasoning capabilities

    What to Track Next¶

    • UI schemas / protocols for generative UI — standardized DSLs for describing generated interfaces
    • Agent observability UX — logs, traces, replay mechanisms for understanding what agents did and why
    • Dynamic modality switching — systems that transition between interface modes mid-task
    • Failure-aware UI components — uncertainty visualization, escalation prompts, confidence indicators
    • Persistent memory + state UX — how generated interfaces maintain context across sessions

    Future Directions¶

    Google Research identifies several extension opportunities:

    • Wider service access — connecting generative UI to more tools and APIs beyond image generation and web search
    • Context and feedback adaptation — incorporating user context, preferences, and feedback to improve generated interfaces over time
    • Increasingly interactive and helpful interfaces — richer UI components, more sophisticated interactions

    Key: Generative UI represents a paradigm shift from application catalogs to on-demand interface synthesis. Users should not settle for generic software if an AI can generate a UI tailored to their workflow. The remaining barriers are generation speed and reliability — both of which improve with model capability.
