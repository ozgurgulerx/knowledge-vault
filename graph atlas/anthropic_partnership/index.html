    Anthropic Partnership¶

    Opening Briefing¶

    Anthropic launched the Claude Partner Network on 12 March 2026, committing $100M (2026) to support partners with training courses, dedicated technical support, and joint market development. The programme is explicitly framed around "enterprise adoption" — partners positioned as the delivery layer that gets customers from proof-of-concept to production, including deployment requirements, compliance, and change management. For Cloud Atlas, the fastest path to partner relevance is to position as a production-grade agent and governance specialist for regulated and data-sensitive enterprises, not a generalist "LLM implementer."

    How Claude Services Partners Operate¶

    Services partners are positioned by Anthropic as a guided delivery function that turns "frontier model access" into "enterprise outcomes." The Partner Network describes partners helping customers identify where Claude adds value, then navigating deployment requirements, compliance, and change management to reach production.

    The programme is structured around enablement + shared GTM assets + technical support on live deals. The network describes scaling the partner-facing team "fivefold" to provide Applied AI engineers and technical architects to scope and execute implementations — a co-delivery model rather than purely referral-based.

    From a commercial mechanics standpoint, Claude's packaging encourages a common engagement split: (1) organisational rollout through "Work/Enterprise" style plans (SSO, SCIM, audit logs, compliance API, retention controls) and (2) bespoke application/agent builds via API and/or cloud-provider hosting. Claude Enterprise is explicitly a seat-plus-usage model with usage billed at API rates and spend caps for cost control — pushing partners to sell adoption + governance as a parallel workstream.

    Claude Code creates a distinct services motion: developer enablement + secure rollout + measurable productivity. Enterprise deployment options include Teams/Enterprise vs direct console vs cloud providers, explicit billing routes, and enterprise controls like managed policy settings, memory investment, pinning model versions, and centralised MCP configuration. This is "services work" because organisations need packaging, guardrails, and telemetry to deploy at scale.

    Programme Structure and Enablement¶

    The Claude services-partner ecosystem has three visible layers:

    1. Claude Partner Network membership — free to join, funded to provide training, technical support, and joint market development.

    2. Enablement infrastructure — Partner Portal sharing materials used internally by Anthropic GTM teams (training content, sales playbooks, co-marketing documentation). Introduces a formal technical certification path starting with Claude Certified Architect, Foundations, with more role-based certifications planned.

    3. Qualification and buyer-discovery — "qualified partners" can be added to a Services Partner Directory, a shortlist for buyers seeking implementers. While Anthropic does not publicly list named tiers (Silver/Gold), the directory listing implies a gating step between "member" and "directory-listed."

    Development Partner Program (DPP)¶

    An explicit opt-in mechanism for model improvement. DPP participants share Claude Code sessions via Anthropic's first-party API, are not eligible for zero data retention, and allow retention "for up to 2 years." In exchange, DPP provides benefits including free Claude Code tokens (up to stated thresholds). For most client work, the default stance is the opposite: commercial product inputs/outputs are not used for training by default, and API inputs/outputs are deleted within 30 days by default. Treat DPP as a separate strategic decision with executive sign-off — "do not opt in unless explicitly required."

    Claude Marketplace¶

    A limited-preview enterprise procurement and distribution layer. Customers with an Anthropic spend commitment can allocate part of it to Claude-powered partner solutions; Anthropic manages invoicing. The initial catalogue includes six launch partners spanning software development, legal workflows, finance analysis, and data platforms. Selection intent: solutions designed for enterprise needs in security, scale, and compliance. For services partners, Marketplace-listed tools become "pre-cleared" in procurement terms — implementation accelerators sell faster than traditional bespoke builds.

    Key: Don't confuse the "Claude Marketplace" (enterprise SaaS procurement) with plugin marketplaces in Claude Code (distribution mechanism for extensions). Claude Code's plugin marketplaces can be used internally by services partners to standardise delivery tooling (skills, hooks, MCP servers) across engagements.

    Technical Delivery Playbook¶

    The most reliable pattern across Claude services engagements is to treat "the model" as only one component in a controlled system: identity, data boundaries, tool access, policy enforcement, deployment topology, and end-to-end observability determine whether the solution is enterprise-grade.

    Integration and deployment choices. Claude can be deployed through first-party offerings (Teams/Enterprise + Claude on web) or via cloud providers. Claude Code docs provide a concrete comparison grid (billing routes, identity models, cost tracking surfaces, and enterprise controls). Recommend Teams/Enterprise for most organisations due to centralised billing and minimal infra setup, while Enterprise adds SSO/domain capture and compliance API access.

    Reliability and performance economics. API service tiers — Standard, Priority, Batch — let services partners align SLAs with cost and latency. Priority Tier reduces "server overloaded" errors during peak times; Batch suits asynchronous work. Price "production-grade" differently from "experimentation."

    Data residency and compliance. Claude's regional compliance guidance separates data residency (where prompts/outputs/history are stored) from inference residency (where requests are processed). Security certifications include SOC 2 Type 2; ISO/IEC 27001/27017/27018; CSA STAR. Regulated-industry compliance capabilities: GDPR with EU/EEA processing; HIPAA support. Position residency selection as a first-class architecture decision.

    Data handling and retention. Baseline for commercial use: no training on commercial inputs/outputs by default, API inputs/outputs deleted within 30 days by default. For stricter regimes, Zero Data Retention (ZDR) endpoints process data in real time and discard immediately. Default patterns: classify workloads into "standard commercial", "ZDR-required", and "never send" (local-only) categories.

    Agent and integration orchestration. MCP is the "integration backbone" that can turn one-off connectors into a reusable delivery asset. For services partners, ship reusable MCP servers and patterns rather than bespoke point integrations.

    Security posture for agentic coding and tooling. Claude Code's security is "permissioned by design": read-only by default, explicit approvals for edits/commands, sandboxing for bash commands, write-scope restrictions, prompt injection mitigations (command blocklists, separate context windows for web-fetch, network request approvals), trust verification for new MCP servers, and encrypted credential storage.

    Observability, monitoring, and governance controls. Claude Code exports telemetry via OpenTelemetry (metrics as time series; events via logs/events protocol). Governance-style controls: server-managed settings delivered at authentication time (including "managed-only" settings such as disabling bypass permissions) and hook events such as ConfigChange for auditing or blocking mid-session configuration changes. Treat these as your "AgentOps control plane."

    Cost and capacity management. Claude Enterprise supports spend caps and usage billing at API rates. Claude Code docs provide concrete cost guidance (average costs and percentile behaviour). Sell "cost governance" as an SLA: define budgets, measure spend per workflow/team, and enforce guardrails.

    Cloud Atlas Positioning and Partnering Plan¶

    Positioning Thesis¶

    Position Cloud Atlas as a governed agent delivery specialist for regulated and data-sensitive enterprises, anchored on three differentiators:

    1. Integration standardisation via MCP — ship reusable MCP servers and patterns rather than bespoke point integrations
    2. AgentOps and observability by default — OpenTelemetry dashboards, ConfigChange audit hooks, spend caps and budget reporting as first-class deliverables
    3. Compliance-minded deployment options — data + inference residency decisions, ZDR where required, retention policies, and documented auditability aligned to Claude's listed certifications

    Technical Prerequisites ("Partner-Ready")¶

    • Production reference architecture — support (a) Anthropic API, (b) cloud-provider route (AWS/GCP/Azure), (c) LLM gateway/proxy pattern, (d) explicit model version pinning for enterprise stability
    • Security and policy baseline — package policy controls using Claude Code's native guardrails: permissioned execution, sandboxing, command blocklists, trust verification for MCP, and server-managed settings patterns. Ship as "policy-as-code" templates
    • Turn-key observability — OpenTelemetry export for Claude Code usage and agent workloads, with a default dashboard tracking usage, costs, tool activity, and ConfigChange events
    • Data posture decision tree — client-facing decision tree distinguishing: standard commercial defaults (no training; 30-day API retention), ZDR endpoints (immediate discard), and DPP opt-in (longer retention; training contribution)

    Business Model and Sales Motions¶

    Sales motion: "proof-to-production sprints" + "AgentOps retainer." Pair a fixed-scope sprint (rapid build with measurable KPI) with an ongoing retainer for monitoring/governance and incremental expansion.

    Co-sell readiness. Build an internal deal desk: standardised security pack, standard SOW modules, and a repeatable "buyer enablement deck" that security/procurement can quickly approve.

    Pricing strategy: Three lanes — Fixed package for discovery + compliance readiness (buyers want certainty early), Milestone-based for PoC/MVP and production hardening (ties to outcomes), Monthly managed service for AgentOps (telemetry + cost governance + drift/quality checks).

    KPIs¶

    Commercial — qualified pipeline influenced by partner motion (co-sell deals, inbound from directory), PoC-to-production conversion rate, average time-to-production for a first use case, attach rate of managed AgentOps retainer after initial build.

    Technical/operational — latency/availability by API service tier, count of overload errors (Priority Tier effectiveness), tool-call success/error rates and "human approval" frequency (permissions friction), telemetry coverage (% of workloads emitting OTel), time-to-detect and time-to-mitigate incidents, spend per workflow/team vs caps, token burn against capacity, configuration drift events (ConfigChange), blocked/denied actions by policy.

    Timeline to Become "Directory-Credible"¶

    Weeks 1–2: Join the Claude Partner Network; start certification; draft Cloud Atlas "security + data posture pack" (retention, residency, ZDR, DPP policy).

    Weeks 3–6: Build a reference implementation (MCP integration + OTel dashboards + policy templates + cost governance).

    Weeks 7–12: Run 2–3 lighthouse engagements (one regulated, one developer productivity/Claude Code, one data-integration-heavy) and capture measurable outcomes for a public reference.

    Quarter 2: Apply to be listed (if not already) and execute 1–2 co-marketing activities aligned to partner tooling and playbooks (webinar, field event, joint solution brief).

    Key Risks and Mitigations¶

    Risk Mitigation
    Data governance mistakes (retention/training) Formalise a "data posture" gate in every engagement, default to non-training commercial settings, treat DPP as separate executive decision
    Prompt injection / tool abuse in agentic workflows Ship deny lists, disable bypass modes, require approval for sensitive tools, segment untrusted content workflows
    Regional/compliance mismatch Make residency and inference region selection explicit in architecture, map workloads to Claude's regional endpoints / cloud provider deployments
    Cost overruns or unclear ROI Build dashboards, cap enforcement, and quarterly value reviews into every SOW
    Marketplace-driven commoditisation Sell "Marketplace implementation accelerators" and "integration + governance wrappers" around Marketplace tools
